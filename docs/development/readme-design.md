# Loop Engine 产品首页设计

本规范落实用户在 2026-10-12 对成熟量化研究项目首页的要求。README 是产品入口，
只介绍已实现并可使用的功能。开发到哪一步，正文与示例就更新到哪一步；未来功能、
阶段状态和验收待办只进入执行计划。视觉统一不等于宣称产品已完成全部开发。

## 视觉语言

采用终端工具的精确感和研究文档的清晰层次。主体使用深墨色与低饱和青绿色，浅色主题
使用灰白与深绿色；不将涨跌颜色、价格闪烁或收益曲线作为装饰。保留自有循环符号，
表达反复研究、验证和记录，而不把符号当成已贯通工作流的架构图。

| 元素 | 规则 |
| --- | --- |
| 字体 | Banner、徽章及后续自制英文展示图使用 Google Sans Code；保留 OFL、来源和摘要。 |
| 正文 | 中文解释、英文产品名与技术标识；GitHub 自身控制正文和代码块字体，不注入 CSS。 |
| 深色 | 背景 `#0c1218`，正文 `#edf5f2`，辅助文字 `#94aab5`，强调 `#8ce0c1`。 |
| 浅色 | 背景 `#f3f7f5`，正文 `#173d32`，辅助文字 `#557268`，强调 `#17785d`。 |
| 页面 | 首屏居中，正文左对齐；二级标题划分主要任务，三级标题只拆分数据与模型接入。 |
| 密度 | 单段解释一个要点；功能约六项；比较和导航使用短表格，步骤使用顺序列表。 |
| 媒体 | 使用静态 SVG 和有事实来源的截图；不加入循环播放 GIF、装饰性大动图或外部追踪。 |

README 不支持网站式 CSS 网格或可控字体加载，因此采用 GitHub 可渲染的 Markdown、
少量 HTML、`picture` 和 SVG。字形轮廓保证品牌英文不因访问者本地字体不同而变化。
资产生成方式与许可见 [品牌资源](../brand/README.md)。

## Banner 与徽章

Banner 维持四个版本：宽屏 `1280×400`、窄屏 `600×400`，各有深浅主题。
左侧字标为主，右侧循环符号为辅；窄屏使用重新排版的资产，不能只把宽屏缩成小字。
只保留项目名、`US EQUITY FACTOR RESEARCH` 和两条简短研究原则。
`RESEARCH / VERIFY / REPEAT` 是品牌表述，不是自动执行状态。

徽章保持八枚、两组，统一 30px 高度、圆角、边线与字体。每枚链接到真实内容：

| 第一组：产品属性 | 第二组：实现职责 |
| --- | --- |
| `Market / US equities` → 研究工作流 | `Rust / control` → loopd |
| `Interface / CLI` → 运行与恢复 | `TypeScript / providers` → providerd |
| `Models / pluggable` → 模型接入 | `Python / research` → loop_research |
| `CI / checks` → Actions 检查 | `PostgreSQL / state` → 数据库指南 |

`CI / checks` 只是检查入口，不绘制静态的通过状态。现阶段不展示不存在的 Release、
未授权的开源许可证、覆盖率、下载量或收益徽章。精确工具版本以锁定清单为准，避免
首屏的版本标签与安装文档各自漂移。gRPC、Parquet 等细节放入架构与能力内容。

导航只保留开始使用、研究工作流、数据与模型、运行与恢复、文档五个入口。
桌面两组徽章各一行，手机自然换行；不使用空格堆砌对齐或要求整行保持不换行。

## 内容结构与写法

| 阅读顺序 | 内容 | 写法与依据 |
| --- | --- | --- |
| 首屏与定位 | 名称、研究对象、价值、导航。 | 一段讲清面向美股因子研究，提供计算和可追溯证据；不用“机构认证”等不可核验承诺。 |
| 核心能力 | 数据、因子、组合统计、独立复核、模型接入、恢复执行。 | 每项用具体动作加产出说明；模块实现不写成自动闭环。 |
| 开始使用 | 平台前提、Bootstrap、构建、诊断、命令帮助。 | 所有命令来自仓库实际入口；服务或私有身份前提写在使用命令之前。 |
| 研究工作流 | 数据准备至证据登记的六步操作顺序。 | 交代快照、FactorSpec、试验记录、账本和报告；不虚构一键运行命令。 |
| 研究完整性 | PIT、结果失效、全局试验、独立计算、事务审计。 | 解释如何判断证据可信，统计一致性与经济有效性各有含义。 |
| 数据与模型 | 数据用途与权限；Provider 协议与部署入口。 | 订阅、账号与地区要求写清；具体申请及参数链接到指南。 |
| 运行与恢复 | 已实现的 `loopctl run` 与 Discovery 操作。 | 正面说明人工逐轮候选生成、预算预留和回执恢复；不列待开发操作。 |
| 系统架构 | 控制、传输、数值、独立复核、元数据、契约职责。 | 表格链接到实际组件；不把仅有骨架的客户端列为产品入口。 |
| 文档导航 | 安装、数据、因子、统计、模型、部署六类任务。 | 使用“要完成的任务 → 指南”，避免散落几十个无上下文链接。 |
| 开发与许可 | 贡献入口、验证命令与准确授权信息。 | 首页不列维护者和联系邮箱；详细进度在维护文档，第三方署名与字体许可保持原文。 |

当前真实行为的核验入口：

- `crates/loopctl/src/main.rs` 和 `docs/development/research-runs-cli.md`：
  CLI 命令和有限轮候选生成。
- `python/loop_research/src/loop_research/cli.py`：数据、因子、回测和统计入口。
- `docs/development/portfolio-statistics.md` 与 `global-statistics.md`：统计口径。
- `docs/development/authorized-reconciliation.md`：独立复核与结果登记。
- `docs/development/native-providers.md`、`cloud-providers.md`、
  `vendor-providers.md`：模型接入协议及能力限制。

## 随阶段维护的任务

本规范与 [执行计划](execution-plan.md) 共用交付顺序，不新增独立服务、文档框架或
另一套功能路线图。每个功能任务的 README 更新放入该任务提交中：

| 交付点 | 首页工作 | 验收 |
| --- | --- | --- |
| 本次文档任务 | 重排产品首页、精修 Banner 与徽章、记录调研与写作规则。 | 本地链接与锚点正确，字体/资产可重生成，桌面与窄屏深浅主题检查；提交推送。 |
| Phase 11.2 | 数值工作流交付后更新研究运行说明，加入真实的候选到评测示例。 | 命令在已安装环境运行，示例来源可追溯、凭据脱敏；不把 fixture 指标当实盘成绩。 |
| Phase 11.3–11.6 | 随反馈、复核、准入和调度交付逐项更新相应能力与操作入口。 | 文案与实际 CLI/API 对应，包含必要前提；不提前加入空标题或占位示例。 |
| Phase 12.1 | 将实际系统职责整理为清晰的架构图，使用 archify。 | 图与 PostgreSQL、权限边界和服务实现一致，不混入已废弃架构。 |
| Phase 12.2–12.4 | Web/TUI 验收后加入真实界面与操作说明，沿用品牌色和英文规范。 | 截图来自交付版本；数据等级、权限和敏感信息检查通过。TUI 字体由用户终端配置，截图可用 Google Sans Code。 |
| Phase 13 | 正式数据和完整研究验收后，增加可复核报告样例。 | 标注区间、数据等级、成本与试验总体；只展示实际生成报告。 |
| Phase 14.1 | 逐项核对最终 README、截图、链接、版本与授权。 | 干净环境命令可执行；首页无进度日志、未来功能占位或过期图片。 |
